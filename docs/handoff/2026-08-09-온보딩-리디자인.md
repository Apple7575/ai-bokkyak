## 1. 이 앱이 뭔가

**모두의 복약** — 고령층을 위한 음성 AI 복약 관리 앱.

- React Native + Expo SDK 54 (managed / CNG), TypeScript
- 코드는 전부 `care-app/` 아래. 저장소 루트의 `src/`는 **옛 Vite 웹 프로토타입이며 수정 금지**(시각 레퍼런스용).
- 백엔드 Supabase, **인증 없음**. 가입하면 6자리 `patient_code`를 발급받는다.
- 사용자는 **고령 어르신**이다. 타이핑을 최소화하는 것이 이 앱의 존재 이유다.

## 2. 지금 상태

### 화면 흐름 (현재)

```
앱 실행
 └ (첫 실행) Onboarding ──> RoleSelect(이름·성별) ──> Tabs(홈)
                                        └ 가입 직후 AI 통화(setup)로 생년월일·약 수집
 └ (재실행)  Tabs
```

라우팅은 `care-app/src/navigation/RootNavigator.tsx`의 `initialRouteName`이 결정한다:

```ts
alarmSid ? "Alarm"
  : !init.role && !init.onboarded ? "Onboarding"
    : !init.role ? "RoleSelect"
      : "Tabs"
```

### 관련 파일

| 파일 | 상태 |
|---|---|
| `care-app/src/screens/OnboardingScreen.tsx` | 동작 중. 말풍선 카드 1장 + TTS 음성 안내 + `[회원가입하기]` |
| `care-app/src/screens/SplashScreen.tsx` | **코드만 있고 라우터에 없다 = 절대 표시되지 않는다** |
| `care-app/src/screens/RoleSelectScreen.tsx` | 동작 중. 이름 + 성별(남/여) 만 받는다 |
| `care-app/assets/splash-icon.png` | 네이티브 스플래시 이미지 (로고 + "모두의 복약" 워드마크) |
| `care-app/assets/logo.png` | 인앱 로고. `src/components/Logo.tsx`가 이걸 렌더 |

### 네이티브 스플래시는 이미 동작한다

`app.json`의 `splash` 설정으로 OS가 그린다. **끌 수 없다** — 앱을 켜고 JS가 로드되기까지 1~3초 동안 반드시 무언가 표시되며, 지정하지 않으면 흰 화면이 뜬다.

```json
"splash": { "image": "./assets/splash-icon.png", "resizeMode": "contain", "backgroundColor": "#FFFFFF" }
```

디자이너 시안은 아래 5장이다. **현재 5장 중 1장만 온전히 존재한다.**

| # | 시안 | 지금 | 할 일 |
|---|---|---|---|
| 1 | 스플래시: 로고 + "말로 쉽게 기록하는 복약 관리" + 점 3개 + 하단 "곁에 든든한 복약 파트너" | 코드만 있고 미사용 | **판단 필요** — §4 참고 |
| 2 | "만나서 반갑습니다!" + **캐릭터 일러스트** + `[다음]` | 텍스트만 존재 | 캐릭터 추가 + 슬라이드화 |
| 3 | "모두의 복약 / 고령 만성질환자를 위한 AI 복약관리 서비스" + 약 일러스트 + "복약 정보를 안전하게 보호해요" + `[시작하기]` | **없음** | 신규 |
| 4 | "시작하기 / 복약 관리를 시작하기 위해 정보를 입력해주세요" · 이름 · 성별(여성/남성) · `[AI 복약관리 시작하기]` | 있음(디자인 다름) | 시안에 맞춰 다듬기 |
| 5 | "안내" — 수집 정보 이용 고지 3항목 + `[확인하고 시작]` | **없음** | 신규 |

**화면 2**
> 만나서 반갑습니다!
> 모두의 복약은 음성 AI가 어르신의 복약을 쉽고 안전하게 관리해 드려요.

**화면 3**
> 모두의 복약
> 고령 만성질환자를 위한 AI 복약관리 서비스
> 복약 정보를 안전하게 보호해요.

**화면 4**
> 복약 관리를 시작하기 위해 정보를 입력해주세요
> 이름 / 성별
> 입력하신 정보는 안전하게 보호돼요.

**화면 5**
> 안내
> 수집된 복약 정보는 혈압·혈당·투약 알림 및 건강 돌봄 지원 서비스에 등록하신 돌봄기관에 제공됩니다.

## 4. 캐릭터 일러스트 — 이 작업의 핵심

`care-app/assets/`에 **캐릭터 이미지가 없다.** 만들어서 넣어야 한다.

### 요구사항

- 시안의 파란 마스코트: 둥근 몸통, 큰 눈, 부드러운 인상
- 브랜드 색과 맞출 것 — `--primary-blue #2563EB`, `--secondary-blue #4F8EF7`, `--light-blue-bg #EEF5FF`
- **배경 투명 PNG**
- 화면 2용(인사하는 포즈), 화면 3용(약/알약 관련) 최소 2종
- 해상도: 표시 크기의 3배 (예: 화면에 160px로 쓸 것이면 480px)
- 파일 위치: `care-app/assets/onboarding/` (새 폴더)
- 파일명: `character-hello.png`, `character-medicine.png` 같은 식으로 의미가 드러나게

### 용량 주의

APK가 이미 49MB다. 일러스트 한 장이 500KB를 넘지 않게 최적화할 것.

## 5. 지켜야 할 제약

### 디자인 토큰만 쓴다

색·폰트를 하드코딩하지 말 것. 반드시 `care-app/src/theme/tokens.ts`에서 가져온다.

```ts
colors.primaryNavy   #102A5E
colors.primaryBlue   #2563EB
colors.secondaryBlue #4F8EF7
colors.lightBlueBg   #EEF5FF
colors.cardBg        #FFFFFF
colors.border        #D8E5F6
colors.text          #1F2937
colors.textSecondary #64748B

fontSizes  body 18 / emphasis 22 / title 24 / hero 40
spacing    xs 4 / sm 8 / md 16 / lg 24 / xl 32
radii      card 16 / button 14 / pill 999
minTouch   56
```

### 고령층 UX

- **본문 18px 이상**, 주요 버튼 **높이 56px 이상**
- 홈 화면은 최근 QA 피드백("텍스트 더 키워야 함")을 반영해 본문을 19~20px, 제목을 26~30px로 올렸다. 온보딩도 이에 맞출 것
- 모든 사용자 노출 문구는 **한국어**

### 상태바 겹침 주의

`ScreenHeader`를 쓰지 않는 화면은 **`useSafeAreaInsets()`로 직접 `paddingTop`을 줘야 한다.** 안 하면 시각·통신사 표시와 글자가 겹친다 (실제로 QA에서 나온 버그다).

```tsx
const insets = useSafeAreaInsets();
<ScrollView contentContainerStyle={[styles.c, { paddingTop: insets.top + spacing.md }]}>
```

### 없는 기능을 있는 것처럼 쓰지 말 것

보호자 기능은 회의 결정으로 **제거됐다**. 화면 5의 "보호자·돌봄기관 보고서" 문구를 그대로 넣으면 거짓 고지가 된다. 개인정보 고지는 특히 정확해야 한다.

참고: `care-app/src/screens/PrivacyScreen.tsx`에 **실제 수집 범위대로 쓴 처리방침**이 이미 있다. 화면 5 문구는 그것과 모순되지 않아야 한다.

### 재사용할 것

- `care-app/src/components/BigButton.tsx` — 큰 버튼 (variant: primary/secondary)
- `care-app/src/components/Logo.tsx` — 로고 이미지
- `care-app/src/components/ScreenHeader.tsx` — 뒤로가기 있는 헤더

## 6. 결정이 필요한 항목

### A-01 인앱 스플래시를 쓸 것인가

화면지도에서 **A-01은 아직 미결정**이다.

- **권장: 쓰지 않는다.** 네이티브 스플래시가 이미 시안 1번과 거의 같은 모습(로고+워드마크)이라, 인앱 스플래시를 추가하면 **로고가 두 번 연달아 뜬다.**
- 굳이 쓴다면 네이티브 스플래시 이미지와 인앱 스플래시의 로고 위치·크기를 **픽셀 단위로 맞춰** 이어지게 해야 한다. 그게 어렵다면 `SplashScreen.tsx`를 지우는 편이 낫다.

**사람이 정해야 한다. 임의로 라우터에 넣지 말 것.**

### 슬라이드 전환 방식

시안 1~3은 슬라이드로 보인다(점 3개 인디케이터). 구현 시:

- 가로 스와이프 + 점 인디케이터 / 또는 `[다음]` 버튼으로만 진행
- **고령층 대상이므로 스와이프만으로는 부족하다.** `[다음]` 버튼을 반드시 함께 둘 것
- 마지막 장에서 `setOnboarded()` 호출 후 `RoleSelect`로 이동

현재 온보딩의 이동 코드:

```ts
async function start() {
  await setOnboarded();          // 다시 보지 않게 표시
  await stopSpeaking();
  nav.reset({ index: 0, routes: [{ name: "RoleSelect" }] });
}
```

### TTS 음성 안내를 유지할 것인가

현재 온보딩은 들어오면 인사말을 **음성으로도 읽어준다**(`speak(GREETING)`). 화면을 떠나면 멈춘다.

슬라이드 3장으로 바뀌면 장마다 읽어줄지, 첫 장만 읽을지 정해야 한다. **권장: 첫 장만.** 넘길 때마다 음성이 끊기고 새로 시작되면 어수선하다.

이탈 시 정리 패턴을 반드시 지킬 것 (네트워크 TTS가 늦게 도착해 다음 화면에서 들리는 사고를 막는다):

```ts
useEffect(() => {
  let cancelled = false;
  speak(GREETING).then((ok) => { if (ok && cancelled) stopSpeaking(); });
  return () => { cancelled = true; stopSpeaking(); };
}, []);
```

## 7. 검증

```bash
cd care-app
npx tsc --noEmit    # 타입 체크 — 반드시 통과
npm test            # jest 19 suites / 159 tests — 반드시 전부 통과
```

- 순수 로직(슬라이드 인덱스 계산 등)을 새로 만들면 `src/lib/`에 두고 **RN/네트워크 의존 없이** 작성한 뒤 `src/__tests__/`에 단위 테스트를 붙인다.
- 화면·음성·알림은 실기기 수동 검증 영역이다. 자동 테스트를 억지로 만들지 말 것.

### 실기기 확인 항목

1. 첫 실행 시 온보딩이 뜨고, 끝내면 다시 안 뜨는지 (`care.onboarded`)
2. 상태바와 글자가 겹치지 않는지 (노치 있는 기기)
3. 캐릭터 이미지가 깨지거나 늘어나지 않는지 (여러 화면 크기)
4. 음성 안내가 화면을 떠난 뒤에도 계속 들리지 않는지

## 8. 작업 범위 밖 (건드리지 말 것)

- **저장소 루트의 `src/`** — 옛 Vite 프로토타입. 수정 금지.
