## 1. 계정 — 법인 명의 Play Console 개설

법인이 이미 있으므로 개인 계정에 올렸다가 이전하지 말고 **처음부터 법인(조직) 계정**에 올린다.
조직 계정은 개인 신규 계정에 걸리는 "테스터 12명 × 14일 비공개 테스트" 의무가 없다.

| ☐ | 할 일 | 누가 | 메모 |
|---|---|---|---|
| ☐ | **D-U-N-S 번호** 확인/발급 | 대표 | 법인 명의. 없으면 Dun & Bradstreet 한국에서 무료 발급(수일~2주). Play 조직 계정 필수 |
| ☐ | 법인용 Google 계정 준비 | 대표 | 개인 Gmail 말고 법인 메일(또는 법인 전용 Google 계정). 나중에 담당자 바뀌어도 계정이 남게 |
| ☐ | Play Console 개발자 계정 등록(조직) | 대표 | https://play.google.com/console · 등록비 US$25(법인 카드) · 조직 이름 = 사업자등록증의 법인명(영문 표기 포함) · D-U-N-S · 법인 주소·전화·웹사이트 |

| ☐ | 개발자 프로필 공개 정보 | 대표 | 스토어에 보이는 개발자명(법인명)·이메일·주소(조직은 주소 공개됨)·전화 |

## 5. 데이터 보안(Data safety) 답안

코드가 실제로 보내는 것만 적는다. 틀리면 정책 위반으로 내려간다.

**공통 질문**
- 데이터를 수집하거나 공유하는가 → **예**
- 전송 중 암호화 → **예**(HTTPS, Supabase)
- 사용자가 삭제를 요청할 수 있는가 → **예** (앱 안 "모든 데이터 삭제" + 웹 `delete-account.html`)
- 독립 보안 검토(MASA) → 아니오

**데이터 유형**

| 유형 | 수집 | 공유 | 필수/선택 | 용도 | 비고 |
|---|---|---|---|---|---|
| 개인 정보 › 이름 | 예 | 아니오 | 필수 | 앱 기능 | 환자 이름 |
| 개인 정보 › 사용자 ID | 예 | 아니오 | 선택 | 앱 기능(기기 교체 시 복구) | 카카오 회원번호. 닉네임은 저장 안 함 |
| 건강 및 피트니스 › **건강 정보** | 예 | 아니오 | 필수 | 앱 기능 | 복약 일정·약 이름·복약 기록·1분 점검 입력(영양제·약·연령대·임신 등 조건)과 결과 |
| 사진 및 동영상 › 사진 | 예(일시 처리) | **아니오** | 선택 | 앱 기능 | 약봉투 사진은 글자 인식(OpenAI)에만 쓰고 저장하지 않음. "임시 처리됨" 체크 |
| 앱 활동 › 앱 상호작용 | 예 | 아니오 | 필수 | 분석 | 알람 울림·응답 시각, 알람 설정 완료 여부(익명) |
| 앱 정보 및 성능 › 비정상 종료 로그 | 아니오 | — | — | — | 크래시 SDK 없음 |
| 기기 ID, 위치, 연락처, 메시지, 오디오, 파일 | 아니오 | — | — | — | 마이크 권한 자체가 없음 |

"공유"는 제3자 전송을 뜻하는데, 사진의 OpenAI 전송은 **서비스 제공자(처리 위탁)** 예외라 "공유 아니오"로 둬도 된다. 개인정보처리방침에는 위탁으로 이미 적혀 있다.

## 6. 전체 화면 인텐트 시연 영상

Play가 USE_FULL_SCREEN_INTENT 신고에 요구한다. 30초~1분, 세로, 실기기 화면 녹화.

1. 홈에서 알람이 2분 뒤로 등록돼 있는 모습.
2. 화면을 끄고 잠근다.
3. 알람이 울려 잠금 화면 위로 알람 화면이 뜬다(약 이름, "지금 약 먹기 / 안 먹고 건너뛰기 / 잠시 미루기" **3개 버튼**).
4. "지금 약 먹기"를 눌러 완료 화면이 나오고 홈으로 돌아간다.

자막에 "보호자에게도 기록"처럼 **없는 기능**을 넣지 말 것. YouTube 비공개(링크 공개) 또는 Google Drive 링크로 제출.

## 7. 실기기 검증 (프로덕션 AAB 기준, 내부 테스트 트랙에서)

Android 13·14·15 각 한 대 이상. 특히 **Android 14 이상**은 알림·정확한 알람·전체화면 정책이 달라서 꼭.

| ☐ | 약봉투 사진 등록 | 카메라 권한 요청, 사진 선택, 이름 칩 생성 |
| ☐ | 카카오 연결 → 앱 삭제 → 재설치 → 카카오로 불러오기 | 약장 복구 |
| ☐ | 더보기 → 처음 화면으로 돌아가기 | 확인창 뜸, 확인 시 Intro |
| ☐ | 개인정보 설정 → 모든 데이터 삭제 | 서버 행 삭제, 알람 전부 취소 |
| ☐ | 글자 크게(시스템 글꼴 최대) | 버튼 글자가 잘리지 않음 |
| ☐ | 다크 모드 | 깨지는 화면 없음 |
| ☐ | Play Console 사전 출시 보고서 | 내부 테스트 업로드 후 자동 생성. 크래시·접근성 경고 확인 |

## 8. 출시 절차

1. **내부 테스트**(최대 100명, 심사 없음) — AAB 업로드 → 테스터 이메일 등록 → 링크로 설치 → 7절 검증.
2. **비공개 테스트**(선택) — 팀원·지인 20명 정도에게 1주. 조직 계정은 의무 아님.
3. **프로덕션** — 등록정보·앱 콘텐츠 선언이 전부 ☑이어야 "검토 제출" 버튼이 열린다. 심사 보통 1~3일, 건강 앱·전체화면 인텐트 신고가 있으면 최대 7일.
4. **단계적 출시** 20% → 50% → 100%. 첫 버전은 100%로 가도 된다(사용자 수가 적음).
5. 국가: 대한민국만.

## 9. 출시 후

- Play Console → Android vitals(비정상 종료·ANR) 매주 확인. ANR은 알람 포그라운드 서비스에서 날 수 있음.
- 리뷰 답변(법인 이름으로).
- 정책 메일은 법인 메일로 온다. 7일 안에 답하지 않으면 앱이 내려갈 수 있으니 메일 담당 지정.
- 다음 빌드부터는 `eas build --profile production` → 내부 테스트 → 프로덕션 반복. versionCode는 자동 증가.
