## 3. 알림 구현 상태 (팀 목록 4번을 코드로 대조)

| 상태 | 팀 항목 | 코드 사실 |
|---|---|---|
| ☑ | Android 13+ 알림 권한 요청과 거절 시 안내 | 일정 저장 시 요청(`ensurePermission`). 거부하면 저장 뒤 "알림이 꺼져 있어요 → 설정 열기" 안내 + 홈 배너(7e88643) |
| ☐ | 알림 **채널** 차단 감지 | **미구현.** 권한은 보지만 채널(아침/점심/저녁/자기 전)만 꺼진 경우는 감지하지 않는다. 심사 필수는 아님. 넣으려면 홈 배너 검사에 `notifee.getChannels()`의 `blocked` 추가(작음) |
| ☑ | 정확한 알람 권한 허용·철회·재허용 | 홈 배너로 설정 이동. 권한 없으면 alarmManager 옵션을 빼고 예약(거부돼도 알람은 비정확하게 울림). 재허용 후 앱을 열면 `resyncAllAlarms`가 정확 알람으로 다시 잡는다(앱 시작·포그라운드 복귀 때 실행) |
| ☑ | USE_EXACT_ALARM 정책 | 쓰지 않음. SCHEDULE_EXACT_ALARM만 사용(사용자가 설정에서 켜는 방식, 신고 불필요) |
| ☑ | 상시 실행 서비스 | 없음. 알람 울리는 동안만 shortService |
| ☐ | 전체 화면 알림 신고 | Console 양식 + 시연 영상(6절) |
| ☐ | 잠금화면 건강정보 노출 | `visibility: PUBLIC`, 약 이름이 제목에 들어감. 2절 "결정" 항목 |
| ☑ | 재부팅·시간/시간대 변경 복구 | `AlarmBootReceiver`가 BOOT_COMPLETED·TIME_SET·TIMEZONE_CHANGED를 받아 HeadlessJS로 재예약 |
| ☑ | 약 수정·삭제 시 옛 알림 취소 | 수정은 "기존 비활성 + 새 일정", 둘 다 `cancelSchedule(id)` 호출. 알림 id가 `alarm-<scheduleId>`라 일정별로 독립(같은 시각 여러 약도 덮어쓰지 않음) |
| ☑ | 강제 종료 후 | OS가 예약 알람을 지운다(모든 앱 공통, 정책상 정상). 앱을 다시 열면 재예약. "최근 앱에서 지우기"는 알람에 영향 없음 |
| ☑ | 반복 방식 | 반복 트리거가 아니라 **매 회차 "다음 1회"만 정확 알람으로 예약**, 울린 직후 다음 회차 재예약. 자정·시간대 변경에 강하지만, 울린 뒤 재예약이 실패하면 다음 회차가 비므로 7절 "자정 전후" 테스트가 중요 |

### 약 정보의 출처·정확성 (팀 항목 2번)

- 출처: 식약처 DUR 병용금기 고시(`dur_contraindication.notice_no`), 식약처 의약품·건강기능식품 품목 자료, 약사 검수 상호작용 규칙(`interaction_rule`, 승인된 것만 `is_active`).
- 갱신: 약사가 규칙을 승인할 때만 바뀜. 앱은 문장을 지어내지 않고 서버 문장을 그대로 보여 준다.
- 설명문·심사 메모에 위 두 줄을 그대로 쓰면 "근거 없는 주장"으로 걸리지 않는다.
- 의료기기 해당 여부: 알람·기록·공개 자료 기반 상호작용 안내는 진단·치료 목적이 아니라 **의료기기에 해당하지 않는다**고 보는 것이 일반적이다. 확정이 필요하면 식약처 "모바일 의료용 앱 안전관리 지침"으로 확인. 설명문의 면책 문장은 그와 별개로 필수.

## 6. 데이터 보안(Data safety) 답안

코드가 실제로 보내는 것만 적는다. 틀리면 정책 위반으로 내려간다. **SDK 현황**: 분석 SDK·오류 수집 SDK·푸시 SDK 없음(알림은 로컬 예약). 카카오 SDK 없음(웹 OAuth). 외부 전송은 Supabase(DB)·OpenAI(약봉투 사진 글자 인식)·카카오(회원번호 조회) 셋.

**공통 질문**
- 데이터를 수집하거나 공유하는가 → **예**
- 전송 중 암호화 → **예**(HTTPS)
- 사용자가 삭제를 요청할 수 있는가 → **예** (앱 안 "모든 데이터 삭제" + 웹 `delete-account.html`)
- 독립 보안 검토(MASA) → 아니오

**데이터 유형**

| 유형 | 수집 | 공유 | 필수/선택 | 용도 | 비고 |
|---|---|---|---|---|---|
| 개인 정보 › 이름 | 예 | 아니오 | 필수 | 앱 기능 | 환자 이름 |
| 개인 정보 › 사용자 ID | 예 | 아니오 | 선택 | 앱 기능(기기 교체 시 복구) | 카카오 회원번호. 닉네임은 저장 안 함 |
| 건강 및 피트니스 › **건강 정보** | 예 | 아니오 | 필수 | 앱 기능 | 복약 일정·약 이름·복약 기록·1분 점검 입력(영양제·약·연령대·임신 등 조건)과 결과. **서버 저장** |
| 사진 및 동영상 › 사진 | 예(일시 처리) | **아니오** | 선택 | 앱 기능 | 약봉투 사진은 글자 인식(OpenAI)에만 쓰고 저장하지 않음. "임시 처리됨" 체크 |
| 앱 활동 › 앱 상호작용 | 예 | 아니오 | 필수 | 분석 | 알람 울림·응답 시각, 알람 설정 완료 여부(익명) |
| 앱 정보 및 성능 › 비정상 종료 로그 | 아니오 | — | — | — | 크래시 SDK 없음 |
| 기기 ID, 위치, 연락처, 메시지, 오디오, 파일 | 아니오 | — | — | — | 마이크 권한 자체가 없음 |

"공유"는 제3자 전송을 뜻하는데, 사진의 OpenAI 전송은 **서비스 제공자(처리 위탁)** 예외라 "공유 아니오"로 둬도 된다. 개인정보처리방침에 위탁으로 적혀 있다.

### 계정 삭제 (팀 항목 3번)

| 상태 | 항목 | 코드 사실 |
|---|---|---|
| ☑ | 앱 안 삭제 경로 | 더보기 → 개인정보 설정 → 모든 데이터 삭제. `patients` 행 delete → 일정·기록·점검 결과·알람 로그가 cascade로 삭제, 예약 알람 전부 취소, 기기 저장값 초기화 |
| ☐ | 웹 삭제 요청 페이지 | `landing/delete-account.html` 코드 있음, **배포 전**. 배포 후 Console "계정 삭제" 양식에 URL 입력 |
| ☐ | 법인명·연락처 일관성 | 2절 항목. 삭제 페이지의 문의 메일도 법인 메일로 |

## 7. 전체 화면 인텐트 시연 영상

Play가 USE_FULL_SCREEN_INTENT 신고에 요구한다. 30초~1분, 세로, 실기기 화면 녹화, **테스트 데이터**로.

1. 홈에서 알람이 2분 뒤로 등록돼 있는 모습.
2. 화면을 끄고 잠근다.
3. 알람이 울려 잠금 화면 위로 알람 화면이 뜬다(약 이름, "지금 약 먹기 / 안 먹고 건너뛰기 / 잠시 미루기" **3개 버튼**).
4. "지금 약 먹기"를 눌러 완료 화면이 나오고 홈으로 돌아간다.

자막에 "보호자에게도 기록"처럼 **없는 기능**을 넣지 말 것. YouTube 비공개(링크 공개) 또는 Google Drive 링크로 제출.

## 8. 실기기 검증 (내부 테스트 트랙에서 설치한 릴리스 빌드로)

Android 13·14·15 각 한 대 이상. **Android 14 이상** 필수(알림·정확한 알람·전체화면 정책이 다름). 팀 목록 5번을 합쳤다.

| ☐ | 확인 | 기대 |
|---|---|---|
| ☐ | Play 내부 테스트 링크로 설치한 빌드 | 사이드로드 APK가 아니라 Play가 서명한 빌드로 아래를 전부 |
| ☐ | 첫 실행 → 이름 입력 → 알람 설정 | 알림 권한 요청이 뜨고, 거부하면 "알림이 꺼져 있어요" 안내 + 홈 배너 |
| ☐ | 알림 권한 거부 → 설정에서 다시 허용 → 앱 복귀 | 배너 사라지고, 다음 알람이 울림(복귀 시 재예약) |
| ☐ | Android 14+ 정확한 알람 권한 | 홈 배너 → 설정 → 켠 뒤 배너 사라짐. 끈 상태에서도 알람은 울리되 수 분 늦을 수 있음 |
| ☐ | 약 등록 → 알림 → 복약 기록 | 기본 흐름 끝까지. 기록 화면에 반영 |
| ☐ | 잠금 화면에서 알람 | 전체화면으로 뜨고 소리가 반복, 3개 버튼 동작, 완료 후 되돌리기 8초 |
| ☐ | 화면 꺼짐·백그라운드·절전 모드·하루 이상 미사용 | 정시에 울림. 제조사 절전(삼성 "절전 앱", 샤오미)은 사용자 설정 문제라 안내 문구로만 |
| ☐ | 알람 3분 이상 방치 | shortService 제한으로 소리가 멈출 수 있음. 알림은 남아야 함 |
| ☐ | 재부팅 후 | 예약 알람 유지(AlarmBootReceiver) |
| ☐ | 시간대 변경·자정 전후 | 23:50 알람 → 울린 뒤 다음날 재예약 확인. 기기 시간대 바꾸면 재예약 |
| ☐ | 약 시간 수정·삭제 | 옛 시각에 알람이 안 울리고 새 시각에만 |
| ☐ | 여러 약을 같은 시각 | 각각 알림이 오고(id가 일정별) 하나도 빠지지 않음. 전체화면은 하나씩 순서대로 뜸 |
| ☐ | 강제 종료(설정 → 강제 중지) 후 | 알람 안 울리는 게 정상. 앱 다시 열면 다음 회차 재예약 |
| ☐ | 비행기 모드 | 홈·약장·기록 "불러오지 못했어요 + 다시 시도", 1분 점검 "인터넷에 연결되지 않았어요" |
| ☐ | 서버 오류 중 복약 응답 | "저장에 실패했어요" 안내가 뜨고 **저장 성공으로 표시되지 않음** |
| ☐ | 1분 점검 | `docs/qa-quick-check-cases.md` A1·B1·B8·C1·D4·E1 최소 6개 |
| ☐ | 약봉투 사진 등록 | 카메라 권한 요청, 사진 선택, 이름 칩 생성 |
| ☐ | 카카오 연결 → 앱 삭제 → 재설치 → 카카오로 불러오기 | 약장 복구 |
| ☐ | 더보기 → 처음 화면으로 돌아가기 | 확인창 뜸, 확인 시 Intro |
| ☐ | 개인정보 설정 → 모든 데이터 삭제 | 서버 행 삭제, 알람 전부 취소, 다시 열면 첫 화면 |
| ☐ | 글자 크게(시스템 글꼴 최대) · 다크 모드 | 버튼 글자가 잘리지 않음, 깨지는 화면 없음 |
| ☐ | Play Console 사전 출시 보고서 | 내부 테스트 업로드 후 자동 생성. 크래시·접근성 경고 확인 |

## 9. 심사자 안내 (Console → 앱 액세스 권한 / 검토 메모)

- 로그인 없음. "지금은 건너뛰기 → 이름 입력"으로 전체 기능 진입.
- 카카오 로그인은 선택 기능(기기 교체 시 기존 정보 복구). 심사자 본인의 카카오 계정으로 시도 가능하며, 없어도 모든 기능 확인 가능. **우리 계정 비밀번호를 적지 않는다.**
- 알람 확인법: 알람 설정에서 시각을 2분 뒤로 → 홈 → 화면 끄기 → 울림.
- 인터넷 필요(1분 점검·약장).
- 스크린샷·영상·심사용 데이터는 전부 **테스트 데이터**(가짜 이름·약 이름).

## 10. 출시 절차

1. **내부 테스트**(최대 100명, 심사 없음) — AAB 업로드 → 테스터 이메일 등록 → 링크로 설치 → 8절 검증.
2. **비공개 테스트**(선택) — 팀원·지인 20명 정도에게 1주.
3. **프로덕션** — 등록정보·앱 콘텐츠 선언이 전부 ☑이어야 "검토 제출" 버튼이 열린다. 심사 보통 1~3일, 건강 앱·전체화면 인텐트 신고가 있으면 최대 7일.
4. **단계적 출시** 20% → 50% → 100%. 첫 버전은 100%로 가도 된다.
5. 국가: 대한민국만.

## 11. 출시 후

- Play Console → Android vitals(비정상 종료·ANR) 매주 확인. ANR은 알람 포그라운드 서비스에서 날 수 있음.
- 리뷰 답변(법인 이름으로).
- 정책 메일은 Console 등록 메일로 온다. 7일 안에 답하지 않으면 앱이 내려갈 수 있으니 메일 담당 지정.
